# 远程训练指令（可直接整段发给远程 AI 助手）

> 用法：把本文件全部内容粘贴给远程服务器上的 AI 助手。尖括号 `<...>` 处按实际环境替换后再发送。
> 本项目路径以 `project/` 为根；官方脚本 `RDSS.py` 等在工作区上一级，**只读不改**。

---

## 0. 你的角色与目标

你是负责在 Linux GPU 服务器上执行「RDSS 课程规模复现」实验的工程助手。目标是按 P0→P4 的顺序跑通整条流水线，产出**可追溯、不编造**的实验结果：

- P0：环境自检（CLIP + WRN-28-2 单批前向形状正确）
- P1：CIFAR-10 数据划分（已生成，需校验）与 CLIP 特征 + 核带宽 σ
- P2：三种选样器索引（random / k-center / RDSS）+ 与官方实现一致性测试
- P3：纯监督 sanity + FixMatch 单次跑通
- P4：18 次主实验矩阵（m ∈ {250,1000} × {random,kcenter,rdss} × 训练种子 {42,1234,12345}）

**硬性纪律**（违反任何一条即视为实验无效）：
1. 不得用测试集做任何决策（调参、选 checkpoint、挑种子）；测试评估只允许由 `train_fixmatch.py` 在训练结束后自动执行一次。
2. 三种方法必须共用同一份 `configs/fixmatch.yaml`、同一份特征、同一个训练池；只在"选样结果"上不同。
3. 不得修改官方根目录脚本（`RDSS.py` / `get_cifar_feature.py` / `visualization.py`）。
4. 不得编造、估算或补写任何指标；失败的 run 如实报告错误与已完成步数。
5. 不得手改 `selections/*.json`、`splits/*.json`、`features/*.npy` 的内容。
6. 选择阶段不用标签：若你新增任何代码，选择器函数签名中不得出现标签参数。

## 2. 数据集与特征配置

### 2.1 CIFAR-10

```bash
python scripts/download_cifar10.py
```

预期：`train=50000 test=10000 classes=10`，数据落在 `project/data/cifar-10-batches-py/`。

### 2.2 固定划分（**已生成，禁止重建**）

`splits/` 下应已有：`val_indices_seed0.json`（5000）、`trainpool_indices_seed0.json`（45000）、`test_indices.json`（10000）、`splits_meta.json`。

若服务器上 **`splits/` 不存在**（只拷贝了代码），先执行一次且仅一次：

```bash
python scripts/split_val.py --val-seed 0 --output splits/    # 不要加 --force
```

然后校验：

```bash
python - <<'PY'
import json, hashlib
from pathlib import Path
m = json.load(open("splits/splits_meta.json"))
print("val_seed =", m["val_seed"], "sizes =", m["val_size"], m["train_pool_size"], m["test_size"])
for name, info in m["files"].items():
    got = hashlib.sha1(Path("splits", name).read_bytes()).hexdigest()
    print(name, "sha1", "OK" if got == info["sha1"] else "MISMATCH")
PY
```

要求：三份 sha1 全部 `OK`，`val_seed=0`。**不要**运行 `split_val.py --force`。

### 2.3 CLIP 特征（ViT-B/32，final [CLS]，L2 归一化）

```bash
python scripts/extract_clip_features.py --dataset cifar10 --model openai/clip-vit-base-patch32 \
    --pool trainpool --indices splits/trainpool_indices_seed0.json \
    --output features/cifar10_trainpool_clip.npy

python scripts/extract_clip_features.py --pool test \
    --output features/cifar10_test_clip.npy
```

预期：`shape=(45000, 768)` 与 `(10000, 768)`，dtype float32；同目录生成 `*.meta.json`（含 `feature_sha1`、`take=cls_last_hidden`、`l2_normalize=true`）。

**可复现性检查**（P1 通过条件）：再抽 2000 条到临时文件，与正式文件前 2000 行逐位比较（不覆盖正式文件）：

```bash
python scripts/extract_clip_features.py --pool trainpool --limit 2000 \
    --output features/_recheck_clip.npy
python - <<'PY'
import numpy as np
a = np.load("features/cifar10_trainpool_clip.npy")[:2000]
b = np.load("features/_recheck_clip.npy")
print("reproducible:", bool(np.array_equal(a, b)), b.shape)
PY
rm -f features/_recheck_clip.npy features/_recheck_clip.meta.json
```

（复核用的参数必须与正式抽取**完全一致**；若默认带 AMP 时不一致，再对正式特征与复核都用 `--no-amp --deterministic` 重跑一次。）

若 `reproducible: False` 且重跑仍失败：在汇报中注明"特征未逐位可复现"，并保留两次的 `meta.json` 供比对，**不要**继续往下跑 P2。

### 2.4 核带宽 σ（median heuristic）

```bash
python scripts/compute_sigma.py --feature-path features/cifar10_trainpool_clip.npy \
    --output configs/kernel.yaml
```

预期：打印 `σ = x.xxxxxx  γ = x.xxxxxx`，并回填 `configs/kernel.yaml` 的 `sigma` / `gamma` / `sigma_source`（**其余注释与 `gamma_official: 0.5` 不得改动**）。同时生成 `features/kernel_sigma_stats.json`。

校验：

```bash
python - <<'PY'
import yaml
k = yaml.safe_load(open("configs/kernel.yaml"))["kernel"]
print("sigma", k["sigma"], "gamma", k["gamma"], "1/sigma", 1 / k["sigma"])
PY
```

要求：`sigma` 与 `gamma` 均非 null，且 `gamma ≈ 1/sigma`（误差 <1e-6）。

选择种子固定为 `42, 1234, 12345`（见 `configs/seeds.yaml`）；预算 m = 250 与 1000 都要做。

```bash
      --output selections/rdss_m${m}.json
done
```

一致性测试（真实特征，官方实现需要开 n×n float64 矩阵，故在 5000 子集上做）：

```bash

    --feature-path features/cifar10_trainpool_clip.npy \
    --budget 250 --n-subset 5000
```

**P2 通过判据**：

## 4. P3：纯监督 sanity → FixMatch 单次跑通

```bash
# 4.1 纯监督 sanity：只用 random_m250_s42 的 250 个标签
python scripts/train_fixmatch.py --config configs/fixmatch.yaml \
    --labeled-list selections/random_m250_s42.json --supervised --seed 42 \
    --output-dir results/p3_sanity_supervised_random_m250_seed42

# 4.2 FixMatch 单次跑通
python scripts/train_fixmatch.py --config configs/fixmatch.yaml \
    --labeled-list selections/random_m250_s42.json \
    --val-indices splits/val_indices_seed0.json --test-indices splits/test_indices.json \
    --seed 42 --output-dir results/p3_sanity_random_m250_seed42
```

**P3 通过判据**：
- 4.1 的 `metrics.json: test.acc` **明显高于 10%**（例如 >40%，否则疑似标签泄漏/映射错误，停止排查）；
- 4.2 正常结束，`test.acc` 高于 10%，且 `mean_mask_ratio` 在 0.1–0.95 之间逐步上升（伪标签开始生效）；
- 每个输出目录含 `train.log / metrics.json / config.yaml / best_model.pth / last.pth`。

若显存不足（`CUDA out of memory`）：按顺序降级并**记录**——
1. `--batch-size 32`（无标签自动变 224）；
2. 仍不足再 `--batch-size 16`；
3. 改动必须同样应用到 P4 的**全部 18 次** run，并在汇报中写明"batch 由 64 降为 X"。

长时间运行请用 `tmux` 或 `nohup`，并把 stdout 落到 `results/logs/` 下，例如：

```bash
mkdir -p results/logs
nohup python scripts/train_fixmatch.py ... > results/logs/p3_sanity.out 2>&1 &
```

## 5. P4：主实验矩阵（18 次 run）

配对规则（必须照此，否则会找不到文件）：
- `random` / `k-center`：**选择种子 = 训练种子**（42/1234/12345 一一配对）；
- `rdss`：选择完全确定性，三个训练种子共用 `selections/rdss_m{预算}.json`。

```bash
for m in 250 1000; do
  for method in random kcenter; do
    for s in 42 1234 12345; do
      mkdir -p results/m${m}/${method}/seed${s}
      nohup python scripts/train_fixmatch.py --config configs/fixmatch.yaml \
        --labeled-list selections/${method}_m${m}_s${s}.json \
        --val-indices splits/val_indices_seed0.json \
        --test-indices splits/test_indices.json \
        --seed $s --output-dir results/m${m}/${method}/seed${s} \
        > results/logs/m${m}_${method}_seed${s}.out 2>&1
    done
  done

  for s in 42 1234 12345; do
    mkdir -p results/m${m}/rdss/seed${s}
    nohup python scripts/train_fixmatch.py --config configs/fixmatch.yaml \
      --labeled-list selections/rdss_m${m}.json \
      --val-indices splits/val_indices_seed0.json \
      --test-indices splits/test_indices.json \
      --seed $s --output-dir results/m${m}/rdss/seed${s} \
      > results/logs/m${m}_rdss_seed${s}.out 2>&1
  done
done
```

> 单卡请**串行**执行（去掉 `nohup ... &` 直接顺序跑也可），避免显存争抢导致 OOM。

每次 run 结束必须检查：

```bash
python - <<'PY'
import json, sys
from pathlib import Path
bad = []
for p in sorted(Path("results").glob("m*/*/seed*/metrics.json")):
    d = json.load(open(p))
    ok = 0 <= d["test"]["acc"] <= 100 and d["steps"] > 0 and Path(p).with_name("best_model.pth").exists()
    print(p.parent, "test_acc=%.2f val_acc=%.2f steps=%d" % (d["test"]["acc"], d["val"]["acc"], d["steps"]), "OK" if ok else "BAD")
    if not ok:
        bad.append(str(p))
print("BAD_COUNT", len(bad)); sys.exit(1 if bad else 0)
PY
```

失败处理：
- 某次 run 报错 → 保留 `.out` 日志与目录，单独重跑该次；**不要**删除已有成功的 run；
- 连续两次 OOM → 按 §4 的降级规则统一降低 batch 后重跑全部；
- 不允许"挑最好种子"：三个种子必须全部报，缺失即标注未完成。

### 5.1 生成回传清单（我后续做汇总用）

```bash
python - <<'PY'
import csv, json

rows = []

        "best_step": d["best_step"],
        "steps": d["steps"],
        "elapsed_sec": d["elapsed_sec"],
        "peak_mem_gb": d["peak_mem_gb"],
        "mean_mask_ratio": d.get("mean_mask_ratio"),
        "gpu": r.get("gpu"),
        "torch": r["versions"]["torch"],

with open("results/p4_manifest.csv", "w", newline="", encoding="utf-8") as f:
    w = csv.DictWriter(f, fieldnames=list(rows[0].keys()))
    w.writeheader(); w.writerows(rows)
print("wrote results/p4_manifest.csv rows=", len(rows))
PY
```
