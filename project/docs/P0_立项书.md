# P0 立项书：CIFAR-10 低标注半监督学习的数据选择（RDSS 课程规模复现）

- 项目：深度学习课程期末项目 PROJECT 03 · NeurIPS 2024（RDSS）
- 定位：**B 层（核心复现）** —— 在缩小预算下复现关键相对趋势
- 范围锁定：CIFAR-10，m ∈ {250, 1000}，仅官方 train/test 划分；SVHN / STL-10 / ImageNet-1k / CIFAR-100 不在范围内（列入"未做项"）
- 状态：P0（立项与审计），P1–P6 见 §8

## 1. 研究问题

在同一冻结 CLIP 特征、同一 FixMatch 训练配方、同一标签预算 m 下，**RDSS（GKHR，代表性与多样性联合最优）选出的 m 个样本，是否比随机选样与 k-center core-set 选样更能提升测试准确率？**
若提升存在，它是否来自"代表性"与"多样性"两个准则的共同作用（α 消融），以及选择过程的成本是否可接受（效率）。

## 2. 可检验假设（预注册，P0 定稿，后续不得修改判据）

| 编号 | 假设 | 判据（先写死，再跑实验） | 判定失败后的动作 |
|---|---|---|---|
| **H1** | 固定预算与配方下，RDSS 的测试性能优于 Random 与 k-center | m=250：mean Acc(RDSS) − mean Acc(Random) **≥ 1.0 pp**，且 mean Acc(RDSS) > mean Acc(k-center)；方向一致性：**≥2/3** 训练种子上 RDSS > Random（配对同训练种子）；m=1000 同式作为趋势验证 | 判定"本课程设置下 H1 不被支持"，保留负结果，按 §7 的三层归因（选择 / 特征 / 半监督优化）分析，禁止只报最好种子 |
| **H2** | 代表性与多样性两端都必要：α=0（只多样性）与 α=1（只代表性）都劣于默认 α=1−1/√m | m=250、默认配方：mean Acc(默认 α) − mean Acc(α=0) **≥ 0.5 pp** 且 − mean Acc(α=1) **≥ 0.5 pp**。若只有一端变差 → 判"部分支持"，并报告哪一端更关键 | 报告"仅一端有效"的事实与可能原因（特征各向异性 / 类别不平衡），不得改判据重跑 |
| **H3** | O(m·n) 增量实现与官方实现等价且显著更快 | ① m=250、同特征同 α 下，索引集合与官方 `RDSS.py` **完全一致（重合率 100%）**；② 选择耗时相对官方 `np.delete` 实现 **≥5×** 加速；③ m=1000（特征已算好）单次选择 **< 5 min** | 若索引不一致但耗时达标 → 判"部分支持"，定位差异来源（γ、α、μ 是否含对角线），把差异写进报告；若耗时未达标 → 记录实际耗时与瓶颈 |

> 判据中的 pp 为绝对百分点（percentage points）。"种子波动"指同方法 3 个训练种子的样本标准差；若方法间差异小于该波动，报告中必须显式说明"差异未超出种子噪声"。

## 4. 成功判据（B 层验收）

1. **主表完整**：m ∈ {250, 1000} × {random, k-center, RDSS} × 3 训练种子，报 mean±std（m=1000 若算力不足则如实标注未完成并估算 GPU 小时）。
2. **可追溯**：每个数字能从 `results/` 原始 `metrics.json` + 配置快照 + 运行命令复算，主表与图表由脚本生成（禁止手工抄写）。
3. **无泄漏**：选择阶段未读标签；验证集只用于选 checkpoint；测试集只在最终报告使用一次。
4. **含分析与成本**：至少 1 项消融（α）、1 项效率统计（选择耗时—m 曲线）、1 项失败/误差分析。
5. **结论措辞合规**：只写"在本课程设置下，方法 A 比基线高 x±y 个百分点"，不写"复现了论文结果"。

## 6. 论文原设置 vs 课程缩减设置（两栏对照）

| 维度 | 论文原设置（NeurIPS 2024） | 课程缩减设置（本立项） |
|---|---|---|
| 数据集 | CIFAR-10 / CIFAR-100 / SVHN / STL-10 / ImageNet-1k | 仅 CIFAR-10 |
| 预算 m | CIFAR-10：{40, 250, 4000} | {250, 1000} |
| 特征 | CLIP ViT-B/32 的 final [CLS] | 同模型；官方脚本实为 `pooler_output`（仅差最后一层 LayerNorm），三方法统一取法 |
| 核带宽 | σ = 全池距离中位数（median heuristic） | 同（另跑 γ=0.5 复现官方行为，作"实现差异"） |
| 基线 | Random / k-Means / Stratified / USL / ActiveFT | Random / **k-center**（课程新增，非论文原基线） |
| 半监督训练器 | USB 封装（FixMatch / FlexMatch / FreeMatch） | 仅 FixMatch，自实现 |
| 训练预算 | USB 1024 steps ≈ 200+ epochs | 100 epochs（单 epoch >5 min 时降为 50 并在报告注明） |
| 主干 | WRN-28-2 | WRN-28-2 |
| 种子数 | 5 | 3（训练种子）；random/k-center 另加 3 个选择种子 |
| 硬件 | 8×A100 40GB | 单卡（≥8GB 显存），混合精度 |
| 主参考数值 | m=250 FlexMatch：Random 93.95±0.31 / k-Means 94.05±0.51 / RDSS 95.50±0.20 | **仅作量级参照，不是验收目标**；要求同设置下方法间排序与趋势一致 |

**边界声明**：课程规模结果不能等同于论文的完整场景结果；数据、预算、迭代步数、训练器、种子数均不同，绝对数值不可直接比较。

## 7. 风险与降级路径（按序执行，每级记录"原计划/降级方案/影响评估"）

| 风险 | 降级方案 | 影响 |
|---|---|---|
| FixMatch 训不通 | 先用选出的 m 个样本做**纯监督**训练，确认 Acc 显著高于 10% 排除标签泄漏，再回查 τ/μ/增强 | 主结果退化为 SL 视角，须在报告中标注 |
| m=1000 算力不足 | 只做满 m=250（论文增益最明显处），m=1000 标注未完成并估算 GPU 小时 | 性能—预算曲线只有两点之一，仍可给趋势 |
| CLIP 特征抽不动（显存/网络/磁盘） | 改用 `resnet50(pretrained=True)` avgpool 2048 维特征，**三方法全部重跑** | 报告中标注"特征变更"，与论文可比性下降 |
| 核矩阵内存过高（n=45000 → 约 8GB） | 分块计算（`kernel.block_rows=5000`）/ float16 / 下采样到 20000 并记录种子 | 主要影响选择耗时与 σ 精度 |
| k-center 太慢 | 用 `sklearn.cluster.KMeans(n_clusters=m).cluster_centers_indices_` 近似 | 须标注"KMeans++ 不等价于 core-set 贪心" |
| 本地 D 盘仅剩 4.1GB | 代码与文档留在本地，数据/特征/权重迁移到远程服务器执行 | 本地不做训练；环境清单以服务器实测为准 |
